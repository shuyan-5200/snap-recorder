# 技术说明

## 核心链路

画面与电脑声音：

`SCStream → Core Image → AVAssetWriter → MP4`

可选人声：

`SCStream microphone output → 独立 AVAssetWriter → M4A`

可选摄像头（0.4.0）：

`AVCaptureSession → AVCaptureVideoDataOutput → 可选本地自然修饰 → 已处理摄像头帧 → Core Image 画中画合成 → 同一 AVAssetWriter`

摄像头预览也读取这份已处理帧，避免预览与最终编码使用两套不同的修饰结果。

没有使用 `SCRecordingOutput`，因为当前链路需要统一处理输出尺寸与暂停 / 继续时间轴。

## 应用图标

正式图标源文件是 `assets/SnapRecorderIcon.svg`，网页副本是 `docs/images/snap-recorder-icon.svg`，两者必须字节一致。图标沿用“器物”系统的拉丝铝、石墨表盘与信号橙录制灯；`scripts/build-app.sh` 会把 SVG 渲染为 1024 像素母版，再生成 macOS 所需的 16–1024 像素 iconset 和 `SnapRecorderIcon.icns`。README、产品页导航、网页 favicon 与安装包均使用这套正式图形。

## 主窗口关闭与进程退出

Snap Recorder 是单主窗口工具。主窗口关闭按钮由 `WindowCoordinator.windowShouldClose` 转成显式退出请求，并延迟到当前 AppKit 关闭回调结束后的下一轮主线程执行，避免同步 `terminate` 与返回 `false` 互相取消。Accessory 模式另外安装最小应用菜单，为 `Command + Q` 提供稳定的 `NSApplication.terminate` 路由。两种入口最终都经过 `applicationShouldTerminate`：空闲时直接退出；倒计时、录制、待处理保存或正在导出时继续使用相应的退出保护流程。

所有退出与保存保护提示统一通过 `WindowCoordinator.runAlert` 显示在当前可见的本应用窗口之上。局部主面板、倒计时及 HUD 使用高层级，普通 `NSAlert.runModal` 原先可能把提示藏在它们下方，却阻止主面板接收点击。提示窗口保持不可共享；延迟打开或置顶请求检测到模态提示时只抬起提示，不抢走其焦点。导出五挡滑块的标签、轨道点击及拖动均可选择档位，窗口背景不参与拖动。

## 隐私隔离

- 任意窗口：`SCContentFilter(desktopIndependentWindow:)`，采集源只包含一个窗口。
- 整屏：`SCContentFilter(display:excludingApplications:exceptingWindows:)`，排除 Snap Recorder 进程，但将主面板列为唯一 `exceptingWindows`。在倒计时隐藏主面板之前取得其 `SCWindow`，避免隐藏后枚举不到。
- 局部：同样使用主面板为唯一例外的显示器过滤器，并把屏幕选区换算为 `SCStreamConfiguration.sourceRect`；不是录完整屏幕后再裁切。
- 倒计时、录制 HUD 和摄像头预览窗口的 `NSWindow.sharingType` 为 `.none`。
- 正式采集在倒计时面板隐藏后才启动。

整屏来源通过 `NSScreen.screens` 与 ScreenCaptureKit 显示器 ID 交集枚举，默认选主面板所在屏幕。`CaptureRequest.displayID` 在倒计时前锁定，采集按 ID 精确匹配；目标断开时失败而不回退到主屏。`SCScreenshotManager.captureImage` 每两秒更新一张最高 640×360 范围内的缩略图，图像只在内存中使用，排除本应用，不采集声音与系统鼠标。切换、录制开始或权限撤销取消预览并清除旧图，异步结果以代际标识隔离。界面按图像真实比例计算缩略图的宽高，只在图像边界绘制细内描边；28×28pt 编号键与刷新键同尺寸，保留 40×40pt 点击区，位于左侧模式文字下方，通过共用水平对齐导线与模式文字右边缘对齐，不占右侧缩略图宽度，单屏隐藏。显示器名称和分辨率同排，整屏详情上移 20pt，缩略图可用高度增至 196pt，图像顶对齐；编号键尽量按图像高度居中，但不覆盖模式选项，多屏过多时只滚动编号键。不移动左侧旋钮锚点，也不改变主窗口高度。

四路卡片的说明共用 `Instrument.text(9.5)`，比此前缩小 1pt，开启、关闭及异常说明均保持两行。上方开关固定，标题与说明成组靠下，底部留 7pt；四张卡片共用 100pt 高度，有权限恢复入口时一起增至 128pt，并统一预留设置行以保持文字基线对齐。四路 `SlideSwitch` 使用共享的 5pt 指示灯间距，比原来增加 2pt；局部选项和人像镜像开关仍使用原来的 3pt。

`WindowCoordinator` 缓存主面板所在显示器 ID，主面板隐藏后仍保留同一呈现屏幕。模态提示先完成原生布局，在成为关键窗口时确认位置；`runModal` 会再次重置窗口层级，因此在模态运行循环开始后用一次性计时器恢复位置与高层级，退出时移除观察器及计时器。状态栏菜单使用主面板视图作为锚点，隐藏时锚定同屏菜单栏区域。HUD、摄像头预览与新打开的局部选区使用该呈现屏幕，而不是受其他应用焦点影响的 `NSScreen.main`。倒计时按当前 `NSScreen.screens` 创建每屏一个面板，使用完整屏幕边界居中；禁止移动、背景拖动和鼠标事件，保持 `.none` 共享策略。屏幕配置变化会重新核对面板，取消与完成清理所有面板，音效仍只有一份。

原生 API 参考：[Apple 单帧截图接口](https://developer.apple.com/documentation/screencapturekit/scscreenshotmanager/captureimage(contentfilter:configuration:completionhandler:))、[NSScreen 屏幕枚举与配置变化](https://developer.apple.com/documentation/appkit/nsscreen/screens)、[NSAlert 原生布局](https://developer.apple.com/documentation/appkit/nsalert/layout())。

## 暂停

ScreenCaptureKit 在暂停期间保持采集，但 writer 丢弃样本。继续时，画面、电脑声音和人声的时间戳统一扣除累计暂停时长，因此最终文件没有静止段或时间空洞。

正式时间轴以第一帧完整画面为起点。第一帧之前的声音样本不会写入；开启人声时还会等待首个人声样本，避免生成静默空轨。

## 摄像头采集与画中画

摄像头使用 AVFoundation 独立视频采集，不在摄像头会话中增加麦克风输入。用户显式开启开关后才请求摄像头权限并启动本地预览；实时预览帧仅在内存中使用，尚未录屏时不保存视频文件。

屏幕帧是最终视频的主时间轴。每次写入屏幕帧时，合成器取可用的摄像头画面，先等比填满正方形区域，再按镜像、圆角方形 / 圆形设置合成到成片指定角落。摄像头帧率与屏幕帧率可以不同；画中画不建立独立视频轨，也不增加最终导出步骤。

默认布局为右下角、中档大小、圆角方形、镜像开启；三档尺寸、四角位置和边距都以输出画布计算，因此不依赖桌面上预览窗口的实际位置。摄像头预览窗口不可共享，整屏与局部过滤器继续排除主面板以外的本应用窗口，避免预览和合成画中画同时进入成片。

摄像头位于四路通道最左侧，开启后人像设置自动从左侧展开为同窗抽屉，不创建独立窗口或系统 popover，也不使用遮罩阻止主面板点击。展开时尽量保持主面板右边缘的位置，空间不足时将整个窗口限制在当前屏幕内；收起恢复 560pt 主面板宽度。抽屉随主窗口一起移动与置顶；四角位置使用 2×2 按钮卡片，完整卡片作为点击区域。进入录制或摄像头关闭时自动收起，减少动画模式下不播放滑出动效。

抽屉不使用滚动区：位置、形状、大小、镜像、自然修饰与完成按钮全部直接显示，辅助说明放入悬停提示。窗口真实宽度以临界阻尼曲线变化（展开 420ms、收起 320ms），内容按当前宽度同步显露；反向操作从当前帧继续，不跳回起点。根视图不把展开宽度设为窗口最小宽度，避免 SwiftUI 自动布局先跳到最终尺寸。

导出整理、选择与进度放在同窗右侧抽屉中。`InstrumentDrawerMetrics` 统一左右卡片为 354×536pt，外侧各留 12pt，抽屉外宽均为 378pt；62pt 标题区、闭合内描边、分隔线与 44pt 底部操作槽共用 `InstrumentDrawer`。标题区和操作槽不随内容压缩，左右使用同一 `InstrumentDrawerField`：刻字标题在上，4pt 后放铺满区块的控件；`InstrumentDrawerDivider` 在组间均匀分配剩余间距。左侧将形状、大小分为上下两排；右侧导出内容与输出方式按钮均等宽，视频大小单独一排，文件名与自定义上限左右对齐。录制时长与“录制”标题同排显示；尺寸、帧率、预计体积或每个视频的上限始终显示，自定义建议范围直接显示在输入框下，不因自定义档或提示信息而隐藏。右侧保存键旁放带回转箭头的“重新录制”，两键共用 44pt 操作高度；不再显示导出完成按钮，与左侧完成键在操作槽内对齐。关闭未保存抽屉和重录均复用未保存确认逻辑。右侧展开固定主窗口左边缘，左侧展开固定右边缘，屏幕空间不足时才整体移入可见区域。三种录制模式及左右抽屉固定使用 560pt 内容区高度，只动画改变窗口宽度。来源标题、旋钮和模式选项固定在顶部锚点，不因右侧说明高度变化而重新居中；录制键上方固定 20pt。抽屉不展开累计文件列表；导出提示最多显示两行，完整文字保留在悬停说明中。取消关闭确认后仍可继续操作。左侧录前设置在导出会话内禁用，导出完成或主动放弃后恢复。

倒计时每个数字出现时播放本机合成的 90ms 单声道电子滴答音，带短促起音与淡出，最后一声略高。`runCountdown` 的退出清理同时停止音频和隐藏面板，取消不留下后续音效；正式录制仍在倒计时结束后才启动，不把提示音录入电脑声音轨。

暂停期间沿用现有 writer 丢弃样本的策略，继续后使用当前摄像头帧。关闭摄像头、停止录制、闲置时关闭主窗口或退出应用都应停止设备采集并清空帧缓存。权限拒绝、设备缺失 / 被占用 / 启动失败需要明确提示；录制中异常断开应进入停止和封装流程，尽力保留已经写入的内容。

摄像头合成发生在首次 H.264 编码之前。导出时对完整画面按所选档位压缩；后续人声合并对已压缩视频样本透传，不再编码画面。真实设备的同步、释放和异常恢复验收仍需在本机完成，状态记录在 `verification.md`。

## 苹果原生自然修饰

自然修饰使用 `original / natural / soft` 三档，默认原图，不再暴露连续数值。“自然”与“柔和”分别采用 0.055 / 0.09 的边缘保留降噪阈值，并以 60% / 85% 的处理图比例混合；仅在保守的人脸区域生效，并对眼、眉、嘴额外留出保护边距。它使用系统自带的 Vision 定位正脸区域，再用 Core Image 处理；不引入付费组件、第三方模型或网络服务，也不做瘦脸、美妆、五官形变。修饰发生在摄像头画中画合成之前，因此不会模糊网页文字或其他桌面内容。光线良好、肤质本已平滑或预览很小时，感知差异可能较小；不把数值差异等同于主观可见程度。

主窗口禁用 `isMovableByWindowBackground`，只保留顶部标题栏拖动，避免 SwiftUI 控件的按住拖动手势被窗口移动抢走。原生全尺寸标题栏已经提供 44pt 拖动区域，因此 SwiftUI 内容不再重复增加 44pt 顶部内边距，只保留 5pt 视觉呼吸区。无摄像头交互验收窗口复用同一 `makeMainWindow()` 创建逻辑，主面板 `sharingType = .readOnly`，辅助面板继续使用 `.none`。录制期间可从菜单栏或再次打开应用唤出主面板；不因允许主面板而放开后续创建的辅助浮窗。

仅在自然修饰开启时检测人脸区域，结果只在内存中用于当前画面处理。区域检测不用于识别身份，不建立或保存人脸模型、特征向量或检测标记。关闭自然修饰后停止该处理路径，关闭摄像头时仍按原有生命周期释放采集与帧缓存。

处理后的摄像头像素同时供预览与编码使用，而不是分别实现两套滤镜。自然程度、转头 / 遮挡时的稳定性和实际录制性能仍需按对应构建完成真实设备验收；实现说明与旧构建结果不能代替 `verification.md` 中的新构建验证。

## 人声与导出

导出表单的五档“视频大小”滑轨独占一排，尺寸、帧率与体积读数铺满其下方；再下方是左右等宽的“文件名”与“自定义上限（MB）”，标题在上，输入框共用高度和内描边。上限框只有选择视频与自定义档时可编辑，其他档位和纯音频时保留并灰显；`GrooveField` 共用禁用底色、文字与细边框，禁用时不绘制焦点或错误强调。自定义建议仍直接显示在输入框下，字段、辅助功能标签与非法文件名提示统一使用“文件名”。

`AppModel.performStartRecording` 在倒计时前快照窗口标题，通过 `ExportPlanning.recordingName` 转为默认文件名；倒计时成功后写入导出会话，取消不修改原名称。标题中的路径分隔符和控制字符被清理，超长标题在 180 UTF-8 字节内按完整字符截断；组合表情的连接符保留。整屏、局部和空标题继续使用临时原片的时间名称，原片路径不改为窗口标题。

- 人声使用 ScreenCaptureKit 的独立 microphone output，与画面共享系统时钟；该接口从 macOS 15 开始提供。
- 电脑声音和人声不能交错写入同一个实时 audio input，因此分别编码为独立临时文件。
- 合并导出通过 `AVAssetReaderAudioMixOutput` 混合电脑声音和人声，仅重新编码 AAC 音频。
- H.264 视频使用压缩样本 passthrough 重新封装；自动自检会比较合并前后的每个压缩视频样本哈希，确保画面没有再次编码。
- `RecordingExportSelection` 将内容集合和单选输出方式分开，支持所有非空内容组合。输出方式只有 `merged / separate`；纯音频不经过视频压缩和视频预算验证。
- 无声视频通过 passthrough 去掉音轨；电脑声音按 48 kHz 双声道、人声按单声道对齐输出 192 kbps M4A，不足视频长度的头尾使用静音补齐，误差阈值为 40 毫秒。
- 每次只生成所选方式需要的文件，先在恢复目录生成全部结果，再统一提交。只合并两路声音时写入 M4A，不添加视频轨。
- 同一次导出的所有文件共用同一个重名后缀。任一步失败都回滚本次已提交的结果，并保留原始视频与人声以便重试。
- 合并音频为 AAC 48 kHz 双声道 / 64–192 kbps（随视频档位）。电脑声音默认降至 78%，人声保持 100%，降低两路叠加时的削波风险。

## 独立窗口画布

窗口模式通过 ScreenCaptureKit 的 `onScreenWindowsOnly` 枚举当前可见窗口，并仅保留标题非空、窗口层级为 0、尺寸至少 100×100，且 `NSRunningApplication.activationPolicy == .regular` 的来源，使列表与 `Command + Tab` 的常规应用范围一致。未命名、最小化、隐藏、其他 Space、桌面、DDPM 等辅助或后台进程、系统层小窗和 Snap Recorder 自身均被排除。ChatGPT 的 bundle ID 与 `Computer Use` / `Computer Use Controls` 标题组合属于已知内部控制窗，也会排除，但 ChatGPT 主窗口保留。同名窗口不合并，窗口 ID 仍是唯一选择依据。候选窗口完成过滤后按“浏览器 / 其他应用”稳定分组：使用明确的浏览器 bundle ID 与应用名称识别 Safari、Chrome、Firefox、Edge、Brave、Arc 等浏览器，避免把同样能够打开网页链接的 ChatGPT 等普通应用误归类；两个分组内部保留 ScreenCaptureKit 的当前前后顺序。开始录制时按所选窗口的 Retina 原始像素确定 MP4 画布，最长边受 3840×2160 上限约束。采集尺寸与输出画布一致，窗口等比完整铺满，不添加桌面背景、圆角、阴影或额外边距。ScreenCaptureKit 使用 `.best` 采集质量。MP4 画布在录制开始后固定；中途改变窗口长宽比时，仍以开始时的比例完成本次录制。

首次读取来源时，用 `CGWindowListCopyWindowInfo` 的前后顺序选择 Snap Recorder 后方最前面的可录窗口，只显示目标框，不激活其他应用。刷新或恢复既有选择也保持被动，避免应用激活通知触发再次刷新而形成焦点闪烁。只有用户从菜单手动改选时，才使用 `NSRunningApplication.activate(options: [.activateAllWindows])` 将目标应用带到普通窗口最前。若同一进程存在多个候选窗口，则必须先取得辅助功能权限，再通过 AX 位置、尺寸和标题匹配目标，执行 `AXRaise` 并设置主窗口 / 焦点；未授权时不退化为应用级置顶，以免错误窗口出现在最前。权限页打开后保留原选择，用户允许并返回程序时自动重试，然后重新激活浮动层级的 Snap Recorder 主面板。目标框是独立的透明 `NSPanel`：使用信号橙闭合圆角描边与柔光、忽略鼠标事件、`sharingType = .none`，并通过 `CGWindowListCopyWindowInfo` 跟随目标窗口位置和尺寸。选中窗口时，另取一次忽略阴影的 `SCScreenshotManager` 内存快照，只读取四角 alpha 边界来估算实际圆角；快照不保留、不写盘，橙色主描边使用该半径，内描边按 1pt 间距缩减半径，保持同心。目标框在倒计时开始前隐藏，不进入成片。

录制阶段保留高质量 H.264 原片到恢复目录，使用 High Profile、CABAC、Rec.709 与最高 30 fps，按像素数使用 24–68 Mbps，保留足够的后续导出余量。导出与录制的预算分开：所有视频档位均按 30 fps 输出；高清保留原生尺寸，目标最高 32 Mbps（仅在原片不超过 30 fps 时允许质量保护回退）；日常/小巧/极小逐步降低尺寸和码率。`ExportPlanning` 统一决定 UI 预估和实际导出参数，原片实际数据量较低时进一步收紧导出预算。旧版 60 fps 原片导出时降为 30 fps，不直接透传。

`AVAssetReaderVideoCompositionOutput` 负责等比缩放、方向变换及旧版原片降帧；`AVAssetWriter` 离线编码允许帧重排。电脑声音单独解码并按档位编码，麦克风绝不进入该读取器。合并人声仅在显式选择时进行。原片不超过 30 fps 时，高清压缩结果若更大，或在 20%/50%/80% 时点的对应帧像素比较低于 32 dB PSNR，则保留原片字节。旧版高帧率原片不能回退为原字节。抽样仅是保守客观保护，不等于整片主观无损保证；抽样读取失败时也仅对符合 30 fps 上限的原片回退。

每次导出都是独立事务：新建临时文件 → 完成压缩/混音/人声对齐 → 自定义视频大小检查 → 统一分配无冲突名称 → 提交结果。自定义输入下限取“极小”档当前音轨配置的预估文件预算（含封装余量），向上取整至 0.1 MB；UI 另外给出到原片体积附近的建议范围。失败与取消只回滚本次结果，保留录制原片和以前成功的导出。完成或关闭导出会话时才清理原片；主动放弃尚未保存的录制移入废纸篓。重复导出始终读取原片，不把上一次低画质输出继续压缩。

自定义大小预留 6% 与 16 KiB 封装空间，并扣除相应音频预算。设置 VideoToolbox 数据量限制后，仍检查每个 MP4 的实际字节数，必要时按测量比例同时减少像素和视频预算重试；四次仍超限则失败，不发布超限结果。这个上限不包含独立 M4A。固定档位保持所选的原片像素比例，体积读数是估算值，不因超过估算而额外缩小画面或报错。预设不靠填充数据制造文件差距，简单画面不保证固定压缩倍数。

详细研究依据与测试见 [导出流程与体积优化](export-redesign.md)。

## 局部选区与聚焦蒙版

局部选区窗口使用 AppKit 透明 `NSPanel`，固定比例只开放四角等比缩放，自定义比例同时开放边缘与四角缩放。选区在主面板所在显示器打开，使用该显示器的逻辑坐标，转换为以左上角为原点的 ScreenCaptureKit point 坐标；输出尺寸再按 `pointPixelScale` 转为 Retina 像素并限制在 3840×2160 内。

选区面板属于 Snap Recorder 自身且 `sharingType` 为 `.none`，采集过滤器也排除主面板以外的自身窗口，因此信号橙虚线、外发光层、灰色蒙版框和 50% 预览遮罩不会进入视频。大选区外发光由比真实选区四边各扩展 14pt 的独立透明 `NSPanel` 绘制，忽略鼠标事件并随选区同步移动、缩放，因此不会挤占录制边界或影响拖动。大选区与小蒙版都提供方角 / 圆角切换并默认圆角。聚焦效果由 Core Image 写入成片：蒙版外先降为单色，再降低一档曝光（线性亮度减半）；蒙版内保留原图。圆角使用随输出尺寸缩放、但受上下限约束的 macOS 风格圆角；大选区还可使用扩展圆角遮罩与高斯羽化形成柔和暗角。

`⌘E` 通过切换选区 `NSPanel.ignoresMouseEvents` 实现可调整与点击穿透状态。全局热键使用 Carbon `RegisterEventHotKey` 按状态临时注册：局部准备态注册 `⌘E`，浮层锁定后额外注册 `⌘R`，录制或暂停时只注册 `Esc`。离开对应状态立即注销，避免常驻抢占应用惯用键。

## 鼠标准星与点击波纹

三种模式都把 `SCStreamConfiguration.showsCursor` 设为 `false`，因此系统箭头永远不会被 ScreenCaptureKit 直接写进画面。用户开启“录制鼠标”时，录制器在每个视频帧上轮询 `CGEvent` 的全局位置与 `CGEventSource.buttonState` 的公开会话按键状态，把坐标映射到独立窗口、显示器或局部选区，再由 Core Image 绘制白色准星（细圆环与四道短刻线，外描 60% 深色）和 0.65 秒点击扩散圆环；尺寸在 `MouseEffectStyle` 中按 1080p 定义，随画面短边在 0.65–2.25 倍之间缩放。关闭选项时不创建跟踪器，也不增加任何鼠标图层。

该实现不安装事件注入或键鼠监听，不要求辅助功能和输入监控权限。暂停期间不更新点击动画，继续录制时会同步当前按键状态并清空旧波纹，避免把暂停期间的点击误写到成片。

## 恢复

录制先以最高画质写到 `~/Library/Application Support/SnapRecorder/Recovery/`。封装成功后等待画质选择；需要人声时同时等待人声导出方式。保存成功后继续保留临时原片，直到用户完成或关闭该会话；失败与取消保留源文件并允许重试。未保存时主动放弃会把原片移入废纸篓。

## 权限

屏幕、系统声音、麦克风和摄像头权限由 macOS TCC 管理。人声和摄像头默认关闭，分别只在用户主动开启时请求对应权限；摄像头开启不请求麦克风权限。应用需要在 Info.plist 中声明摄像头用途 `NSCameraUsageDescription`，并在正式安装位置完成首次系统授权。应用未启用沙盒。本地构建使用 ad-hoc 签名，并显式固定 designated requirement，避免每次重新构建后因 CDHash 改变而被 TCC 识别成新的录屏应用；公开分发仍应使用 Developer ID 签名与公证。首次从旧签名迁移到稳定签名时，需要在“系统设置 → 隐私与安全性 → 屏幕与系统音频录制”中移除旧条目，并只对最终安装位置中的应用重新授权一次。

主面板例外与辅助窗口排除使用苹果的 [excludingApplications / exceptingWindows](https://developer.apple.com/documentation/screencapturekit/sccontentfilter/init(display:excludingapplications:exceptingwindows:)) 组合。应用排除会覆盖之后新建的浮窗，无需逐次枚举 HUD；主面板保持单一窗口身份，隐藏和重新显示不改变例外。窗口枚举异常时停止启动，不退回“什么都录”。`--self-test-window-capture` 是需要既有屏幕权限的显式集成测试，使用纯色窗口和新建辅助面板，裁切录制自有窗口内部并解码检查，临时媒体测试后清理。
