# 录制后的导出流程与体积优化

2026-09-19。0.5.0 / build 13。

> 历史方案与当时的 60/24 fps 实测记录。当前版本的采集与全部视频档位统一为最高 30 fps；下表帧率和体积数据仅用于回溯旧版实验，不代表当前输出。

## 结论

录制结束是进入导出工作区，不能等同于已保存。用户先勾选内容、选择输出方式和大小，同时命名，再保存到下载；原片保留到本次工作结束，所以可以补导出、取消、放弃或直接重录。

麦克风与电脑声音在原来的采集阶段已经是两路，问题主要来自默认选择了混合导出。本次有人声时默认使用“分轨”：无声视频、电脑声音和麦克风各自输出。需要直接播放带解说的成片时，仍可主动选择“合并”。

原高清使用 24–68 Mbps 录制预算，小体积版本仍然保持原尺寸和帧率，只把目标码率除以三。这个目标既不能保证体积差距，也不能证明高清的所有字节都冗余。实测中复杂动态纹理降码率会明显损失细节，因此高清采用保守压缩与质量回退，小体积档用尺寸、帧率和实际文件体积共同控制。

## 操作流程

1. 结束录制，完成临时封装；停止摄像头占用。
2. 导出工作区依次显示内容勾选、输出方式、视频大小和名称。默认勾选已录内容、使用“日常”，有麦克风时默认“分轨”。名称默认日期时间，可直接修改。
3. 确认后写入下载目录。声音与视频先全部生成，再统一提交；同名自动编号。
4. 保存成功后仍留在原页，显示文件名和实际体积，可换画质、名称或声音版本继续导出。
5. “取消导出”回到工作区；“放弃此次录制”把未保存的临时原片移入废纸篓；“重新录制”保留来源设定并重新倒计时。
6. “完成”或关闭已保存的工作区才清理临时原片。已有导出不被删除。关闭尚未保存的工作区时可继续导出或放弃，不再强制保存。

默认命名为 `Snap 录屏 YYYY-MM-DD HH.mm.ss`。自定义名称也支持中文，拒绝路径字符、隐藏文件名和过长名称；统一添加后缀，避免产生目录穿越或覆盖已有文件。

## 内容与输出方式

内容“视频 / 电脑声音 / 人声”分别勾选；每次单选“合并 / 分轨”。只选声音时隐藏视频大小，残留的视频大小输入不会影响纯音频导出。未录制的声音不可勾选。按钮仅保留名称，解释放在悬停提示。

- 合并：所选内容输出一个文件；含视频为 MP4，只有声音为 M4A。
- 分轨：每项一个文件。视频必定无声；电脑声音为双声道 M4A，人声为单声道 M4A。

内容、输出方式和大小使用细边框分组，输出方式使用紧凑选项；名称行独立留白，放弃和重录按钮增加边框。界面保留单页、短标题、单次确认。保存后所有设置仍可操作，无需选择多个输出版本。

## 档位和体积预算

| 档位 | 尺寸/帧率上限 | 视频目标预算 | 用途 |
| --- | --- | --- | --- |
| 高清 | 原始尺寸 / 60 fps | 1080p 约 12 Mbps；4K 约 32 Mbps | 优先保住原始细节 |
| 日常（默认） | 1080p / 30 fps | 最高 4 Mbps | 日常演示 |
| 小巧 | 720p / 30 fps | 最高 1.2 Mbps | 便于分享 |
| 极小 | 480p / 24 fps | 最高 0.4 Mbps | 随手记录，小字会变模糊 |
| 自定义 | 按时长和预算适配 | 用户填写每个 MP4 的 MB 上限 | 明确的文件大小约束 |

始终等比缩放，不放大低分辨率来源。竖屏使用旋转后的宽高边界。小区域和数据量已经很低的原片会进一步降低预算。合入视频的电脑声音随档位为 192/128/96/64 kbps；独立电脑声音为双声道 192 kbps，纯音频混合为双声道 192 kbps；独立人声始终为单声道 AAC-LC 48 kHz / 192 kbps。

平均码率只是一项编码目标。本次同时设置 VideoToolbox 的时间窗口数据上限，但不会只信任编码器参数：日常、小巧、极小还会检查“时长 × 编码预算 + 音频与封装余量”对应的实际文件大小。复杂纹理达到编码器压缩能力下限时，再次降低像素与码率。**档位尺寸是上限，极复杂画面的实际尺寸可以更低。**

自定义上限足够容纳原片时直接保留原片，不为导出而再次降质；需要压缩时预留音频和封装开销；每个 MP4 必须实际不超过输入大小。最多四次编码；仍无法满足则明确失败、保留原片，不交付超限或截短的视频。独立 M4A 不计入单个 MP4 的上限。

高清不追求固定缩小倍数：如果压缩结果更大，或三个时点的对应解码帧低于 32 dB PSNR，则使用原片。抽样无法读取时同样回退。PSNR 是像素差异的客观指标，抽样不等于全片无损或主观质量保证；高清预算也不是硬性文件上限。

## 官方依据与工程判断

- 苹果将 [AVVideoAverageBitRateKey](https://developer.apple.com/documentation/avfoundation/avvideoaveragebitratekey) 定义为平均码率。对应的 VideoToolbox SDK 文档明确把平均码率称为软目标，允许超出或低于目标；所以只设平均码率不能承诺文件大小。
- [DataRateLimits 技术说明](https://developer.apple.com/library/archive/qa/qa1958/_index.html) 说明可以用时间窗口限制编码数据。本机 SDK 的 `AVVideoSettings.h` 允许在压缩设置中传入 VideoToolbox 属性；实际结果仍需要量测。
- [renderSize](https://developer.apple.com/documentation/avfoundation/avvideocomposition/rendersize) 与 [frameDuration](https://developer.apple.com/documentation/avfoundation/avmutablevideocomposition/frameduration) 分别控制合成尺寸和帧间隔。本次用它们降低小体积档的像素和帧数，保留完整画面比例。
- [AVAssetExportSession](https://developer.apple.com/documentation/avfoundation/avassetexportsession) 也提供文件长度限制和多遍处理能力。本次沿用已有 Reader/Writer 导出链路，以便精确控制独立人声、视频透传和事务回滚，没有增加新的运行依赖。
- 本次保留 H.264 MP4，减少对既有播放与后续处理流程的影响；没有把更换编码格式等同于必然改善清晰度。码率、尺寸与画面复杂度需要共同判断。

## 实测及边界

使用纯生成的 4 秒 1920×1080 / 60 fps 测试片：左半边包含文字，右半边是高频变化的块状纹理，刻意比普通静态网页难压缩。旧版编码设置生成的原片为 12,008,902 bytes。

| 输出 | 实际尺寸 | 实际大小（十进制 MB，约数） |
| --- | --- | --- |
| 高清 | 1920×1080 / 60 fps | 12.01 MB |
| 日常 | 1136×638 / 30 fps | 1.87 MB |
| 小巧 | 618×348 / 30 fps | 0.61 MB |
| 极小 | 408×230 / 24 fps | 0.21 MB |
| 自定义 ≤0.35 MB | 490×276 / 24 fps | 0.33 MB |

高清压缩候选曾在该压力样本上得到约 26.8 dB 的全帧比较结果，触发保留原片。最终保留 12.01 MB 原片，是复杂内容下主动保留细节的选择。其他档位按实际预算缩小，不能用压力样本的缩小倍数承诺所有录屏。

自动测试还用 440 Hz 代表电脑声音、880 Hz 代表麦克风，解码检查各独立输出中的两种频率，验证软件音轨没有混入另一来源。扬声器外放被物理麦克风收到属于声学串音，不是软件音轨分离能消除的内容。
